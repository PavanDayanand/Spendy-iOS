# Recommended build order

1.  Xcode project and target.
2.  `App` + scenes/windows.
3.  Design system: fonts, colors, spacing, shapes.
4.  Root navigation: `TabView`, `NavigationStack`, or
    `NavigationSplitView`.
5.  Screen layout: stacks, grids, lists, forms, scroll views.
6.  Reusable components.
7.  State/data flow: `@State`, `@Binding`, Observation, environment.
8.  Models and persistence with SwiftData when appropriate.
9.  Networking with `URLSession` + Swift concurrency.
10. Inputs and validation.
11. Presentations: sheet, full-screen cover, popover, alert,
    confirmation dialog, inspector.
12. System UI: Apple Pay, StoreKit, Photos, Files, Quick Look, Maps,
    authentication.
13. Animation, SF Symbols, haptics/sensory feedback.
14. Accessibility and Dynamic Type.
15. Localization.
16. iPhone/iPad/Mac/watch/visionOS adaptation where applicable.
17. Widgets, Live Activities, App Intents/extensions if needed.
18. Tests, previews, profiling, and accessibility testing.
19. Signing, TestFlight, App Store release.

# Rules for an AI coding agent

Prefer the Apple-native API for the job:

``` text
Bottom sheet        -> .sheet()
Full screen         -> .fullScreenCover()
Floating card       -> .popover()
Alert               -> .alert()
Action sheet        -> .confirmationDialog()
Inspector           -> .inspector()
Sheet size          -> .presentationDetents()
Fitted presentation -> .presentationSizing()
Liquid Glass        -> .glassEffect()
Apple Pay            -> PassKit
App Store purchases -> StoreKit
Photos              -> PhotosUI
Files               -> fileImporter/fileExporter/fileMover
Document preview    -> Quick Look
Maps                -> MapKit
Web                 -> SafariServices/WebKit
Authentication      -> AuthenticationServices
Biometrics          -> LocalAuthentication
Notifications       -> UserNotifications
Widgets              -> WidgetKit
Live Activities      -> ActivityKit
Shortcuts            -> AppIntents
```

Avoid inventing a custom version of a system-owned experience when Apple
already provides it. Avoid deprecated navigation patterns for new
projects. Prefer modern Swift Observation for new code where supported.
Design adaptively instead of hard-coding device dimensions.
