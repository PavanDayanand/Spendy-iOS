# Platform lenses

Use this to choose which live HIG pages to read. These are decision prompts, not substitute guidelines. Review the corresponding “Designing for…” page, the component's platform considerations, and the target OS behavior before implementation.

| Platform | Design questions | Starting source |
| --- | --- | --- |
| iOS | Is the interface comfortable in the hand, useful for both quick checks and longer sessions, and adaptable to orientation and device size? Are touch, text entry, voice, and sensor-driven interactions appropriate? | [Designing for iOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-ios) |
| iPadOS | Does the design use the larger display and support resizing, multitasking, keyboard, pointer, Pencil, touch, voice, and drag and drop where relevant? | [Designing for iPadOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-ipados) |
| macOS | Does it behave well in resizable windows, multi-display work, long sessions, and transitions between active and inactive apps? Can people use keyboard, pointer, and standard Mac menus? | [Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos) |
| tvOS | Is the interface readable from across the room and navigable by focus, remote, controller, and voice? Does it suit immersive viewing and playback? | [Designing for tvOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-tvos) |
| visionOS | Have you chosen window, volume, or immersive space deliberately? Does the experience respect field of view, depth, comfort, passthrough, gaze and hand input, and shared activities? | [Designing for visionOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-visionos) |
| watchOS | Is the experience glanceable and concise, including its complication, widget, notification, Always On, Digital Crown, and Action button behavior where relevant? | [Designing for watchOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-watchos) |
| Games | Can people enter play quickly, use each platform's default input, read text and use controls on every supported display, and personalize/access the game? | [Designing for games](https://developer.apple.com/design/human-interface-guidelines/designing-for-games) |
| iPhone Duo | Does the interface resize and preserve function as the device changes display and pose? Are controls placed and prioritized using the system's current layout guidance? | [Designing for iPhone Duo](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo) |

For work spanning platforms, assess each platform independently before reusing a component or navigation model. Consult [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Inputs](https://developer.apple.com/design/human-interface-guidelines/inputs), and the exact component page for differences.
